# YouCloud Web

YouCloud в браузере: сайт и Worker на Cloudflare, логика целиком на устройстве слушателя.

## Как устроено

- **Сайт** (`src/`) — Svelte 5 + Vite. Всё, что решает, что и как спросить у сервисов, работает в браузере.
- **Worker** (`worker/index.ts`) отдаёт сайт и пересылает его запросы к сервисам: `/x/<хост>/<путь>` → `https://<хост>/<путь>`, с заголовками, которые ждёт каждый сервис. Пускает только к хостам сервисов и только запросы самого сайта. Ничего не хранит.
- **Расширение** (`extension/`) нужно для Яндекс Музыки и аудио YouTube. Они не обслуживают IP Cloudflare: Яндекс отвечает 451, YouTube просит «подтвердить, что вы не бот». Расширение отправляет эти запросы из браузера слушателя, с его IP. Без расширения работают SoundCloud и поиск YouTube.

| Сервис | Без расширения | С расширением |
| --- | --- | --- |
| SoundCloud | ✅ | ✅ |
| Яндекс Музыка | ❌ 451 | ✅ |
| YouTube Music: поиск, подборки | ✅ | ✅ |
| YouTube Music: аудио | ❌ | ✅ с домашнего IP; через VPN — с входом в YouTube в этом браузере |

Обложки и звук SoundCloud сайт берёт прямо с CDN SoundCloud. Где SoundCloud заблокирован (ПК без VPN),
они идут через Worker: проба при загрузке и любая упавшая обложка или поток переключают сайт
(`src/lib/media.svelte.ts`), а Worker переписывает адреса внутри HLS-плейлистов на `/x/…`, потому что
Chrome сам играет HLS и иначе брал бы куски с CDN напрямую.

Ссылку на звук YouTube, которую не стал играть `<audio>`, сайт не держит в кэше: тот же трек
запрашивается у следующего клиента YouTube (до трёх попыток).

Два следующих трека очереди сайт готовит заранее, как приложение: когда текущий заиграл, по очереди
берёт их ссылки на звук и начинает буферизовать каждый в своём `<audio>`. Когда до такого трека
доходит очередь, плеер переключается на его `<audio>`, и трек начинает играть сразу, без запроса к
сервису (`src/lib/state.svelte.ts`, раздел ahead). При включённой экономии трафика в браузере ничего
заранее не грузится.

В «Моей волне» и в радио на месте «Перемешать» стоит «Не нравится», как в приложении: Rotor получает
dislike, Яндекс помечает трек «Не рекомендовать», YouTube Music ставит дизлайк, и сайт больше не
добавляет этот трек ни в одно радио. У SoundCloud дизлайка нет, там работает только последнее.

## Masaki

В браузере Masaki (github.com/GXUser7/Masaki) расширение не нужно и не работает: Masaki сам отвечает
на сообщения сайта (hello с `host: 'masaki'`), ходит в Яндекс и YouTube с IP пользователя и открывает
входы в сервисы своими вкладками. Сайт там без своего фона — лежит на стекле Masaki, берёт его тему
(событие `theme`) и скругления; друзья, очередь и текст выезжают поверх страницы. Мини-плеер Masaki
читает Media Session сайта: обложку, название, позицию и кнопки «следующий/предыдущий».

Раскладка: всё сверху одной шапкой — YouCloud слева, по центру поиск с сервисами внутри (выбранный сервис — и что показывает страница, и где ищет поиск), справа друзья и профиль; внизу плеер одной полосой в одну строку. Главная сервиса — в одной из трёх раскладок на выбор в настройках: «Бенто» (плитки разного размера), «Сцена» (большая карусель в цветах обложки) и «Для тебя» (приветствие и быстрые плитки); под ней твои плейлисты, артисты и подборки. Сайт на русском и английском — язык переключается в настройках.

## Разработка

```bash
npm install
npm run dev      # http://localhost:5190 — сайт и Worker вместе
npm run check    # типы сайта и Worker
```

```bash
npx wrangler login   # один раз
npm run deploy       # собрать и выложить
```

## Расширение

Сайт сам раздаёт расширение: `/youcloud-extension.zip`. Сборка упаковывает папку `extension/` в zip (`scripts/extension-zip.ts`), а дев-сервер собирает его на лету. Карточка с кнопкой «Скачать» и шагами установки есть в «Настройках», а на главных Яндекса и YouTube она появляется, если расширения нет.

**Chrome, Edge, Яндекс Браузер, Opera:** скачать zip → открыть `chrome://extensions` и включить «Режим разработчика» → перетащить zip на эту страницу. Chrome ставит zip как распакованное расширение, распаковывать не нужно. Запасной путь: распаковать zip и нажать «Загрузить распакованное».

Уже открытые вкладки сайта получают расширение сразу после установки, без перезагрузки: `background.js` подключает `bridge.js` к ним в `onInstalled`.

**Обновление:** поднять `version` в `extension/manifest.json` и выложить сайт. Карточка в «Настройках» сама предложит новую версию: её zip перетаскивается поверх старой. ID расширения закреплён полем `key` в манифесте, поэтому новая версия заменяет старую, а не встаёт рядом. Приватный ключ лежит в `YouCloud-keys/youcloud-extension.pem`: он понадобится только для публикации в Chrome Web Store с тем же ID.

**Firefox:** `about:debugging#/runtime/this-firefox` → «Загрузить временное дополнение» → скачанный zip. Такое дополнение живёт до перезапуска Firefox. В Firefox расширение пока не проверено.

**Вход в сервисы** делается в «Настройках» и через расширение, токены копировать не нужно:
- **SoundCloud:** войди на soundcloud.com в этом же браузере и нажми «Войти». Расширение возьмёт сессию из cookie `oauth_token`. Без расширения токен можно вставить вручную.
- **YouTube Music:** берёт вход этого браузера на youtube.com. Расширение подписывает запросы сессией (cookie и `SAPISIDHASH`), и cookie не попадают на страницу.
- **Друзья и «Любимое» (аккаунт YouCloud):** ник и пароль, тот же аккаунт, что в приложении. Со входом сердечко — это «Любимое» аккаунта, общее с приложением: всё лайкнутое на телефоне собрано на странице ♥ в шапке, а лайк здесь телефон скачает.
- **Яндекс:** откроется вход Яндекс ID. Расширение поймает токен на странице, куда Яндекс перенаправит после входа, и закроет вкладку. Без Яндекс Плюса треки играют 30 секунд.

Токены хранятся только в localStorage этого браузера.

Расширение работает только на страницах YouCloud (адреса в `content_scripts` манифеста) и ходит только к хостам Яндекса и YouTube из `host_permissions`. Если сайт переедет на другой адрес, его нужно вписать в `matches`.

## Помощник YouCloud

Маленькая программа рядом с расширением (`helper/`, Go) — для того, до чего расширение изнутри браузера не дотягивается. Нужно расширение 0.6 и новее; в Masaki помощник не нужен, там всё это встроено.

- **Звук YouTube через yt-dlp**, как в приложении и в Masaki. Клиентам сайта YouTube многим трекам отказывает («подтвердите, что вы не бот», поток без PO-токена обрывается на первом мегабайте), а yt-dlp их достаёт. Сайт спрашивает yt-dlp первым (сообщение `yt-stream`), при отказе — своих клиентов.
- **Статус в Discord** «Слушает YouCloud»: трек, исполнитель, обложка, полоска времени, кнопка «Открыть YouCloud». Переключатель — в карточке помощника в «Настройках», выключен по умолчанию. Сайт шлёт только перемены (трек, пауза, перемотка), помощник говорит с запущенным Discord по его локальному каналу (`discord-ipc-N`). Приложение Discord «YouCloud» то же, что у Masaki. Закрыли вкладку — статус снят.

**Как устроено.** Native Messaging: браузер сам запускает помощника, когда расширение к нему обращается, и закрывает, когда отпускает (расширение отпускает его через 15 с после того, как закрыта последняя вкладка YouCloud). Помощник живёт в папке пользователя (`%LOCALAPPDATA%\YouCloud Helper`, на Mac `~/Library/Application Support/YouCloud Helper`) и туда же скачивает yt-dlp (ночные сборки, сверка с SHA2-256SUMS, проверка обновления раз в сутки и после сбоя) и движок JavaScript для YouTube: Deno или Node 20+, если они уже есть, иначе Deno с его GitHub, со сверкой суммы. Сначала yt-dlp идёт без входа; при отказе — с куками youtube.com этого браузера, которые расширение передаёт помощнику, во временном файле на время запуска. Короткий журнал ошибок — `helper.log` в той же папке.

**Раздача и установка.** Сайт раздаёт `/youcloud-helper.exe` и `/youcloud-helper-mac.zip` (одна программа для Apple и Intel). Собирает их `scripts/helper-build.ts` — нужен Go (`winget install GoLang.Go`); дев-сервер собирает при первом запросе. Запущенный руками, помощник ставит себя сам: копирует себя в свою папку и прописывается браузерам (Chrome, Edge, Яндекс Браузер, Opera, Brave, Vivaldi, Chromium, Firefox) — в HKCU на Windows, в папки `NativeMessagingHosts` на Mac; права администратора не нужны. Запущенный ещё раз — проверяет установку и предлагает удалить себя (или `--uninstall`). Подписи нет: Windows предупреждает через SmartScreen, Mac — «Всё равно открыть» в «Конфиденциальности и безопасности»; шаги — в карточке. Мак-версию проверить на Windows нечем.

**Обновление:** поднять `version` в `helper/version.json` и выложить сайт — карточка предложит скачать новую версию, она встанет поверх.

**Проверка:** `npm run test:helper` — настоящий Chromium с расширением, помощник под тестовым именем во временной папке, подставные yt-dlp и Discord (YouTube и настоящий Discord не трогаются), снимки карточки в `test-output/`. Порт 5190 должен быть свободен: тест сам запускает дев-сервер.
